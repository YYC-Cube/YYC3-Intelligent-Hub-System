## 二、修复实录（依托测试文档闭环）

### P1 高优先级：明文密码回退缺陷 → 已修复 ✅

**根因**：[auth-context.tsx] 历史演进遗留 `foundUser.password !== password` 回退分支，使旧明文记录永久有效。

**修复方案**（三件套）：

1. **删除死代码** [app/lib/auth.ts]（硬编码明文密码 mock，全仓零引用）
2. **新建唯一事实源** [lib/yyc3/password.ts](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/lib/yyc3/password.ts)：
   - PBKDF2-SHA-256 / 100,000 迭代 / 16 字节随机盐 / 常量时间比较
   - 自描述存储格式 `pbkdf2$<iter>$<saltB64>$<hashB64>`（支持未来代价因子演进）
   - `verifyPassword` 自动识别三种历史格式，命中旧格式返回 `upgradedHash`
3. **auth-context 一次性升级迁移**：登录校验通过后，旧 SHA-256/明文记录自动升级为 PBKDF2 并 **delete 明文字段** 持久化 —— 用户无感、明文清零

**测试闭环**：新增 [tests/unit/password.test.ts](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/tests/unit/password.test.ts) 5 用例（PBKDF2 格式与盐随机 / 现行校验通过失败 / legacy 升级 / 明文升级清除 / 损坏记录安全拒绝），5/5 通过；全量回归 33 files / 289 passed。

### 中优先级整改计划：AI 服务层 any 治理

- 范围：app/services/ai/core（49 处）+ database.ts（12 处）+ 其余散点（39 处）
- 策略：算法引擎以「类型收窄 + 领域类型定义」渐进替换，禁止一次性大改（回归风险）；随模块迭代逐文件清零，每文件提交独立 PR 附测试
