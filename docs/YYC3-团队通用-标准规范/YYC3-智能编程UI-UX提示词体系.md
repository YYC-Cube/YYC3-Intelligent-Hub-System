# YYC3集成中心系统 · UI/UX全链路闭环提示词体系

本体系基于项目「企业级iPaaS集成平台」定位与「Next.js 16 + React 19 + TypeScript 5 + Tailwind CSS v3」技术栈定制，覆盖**全局页面系统底座、视觉交互感知、操作逻辑行为**三大核心维度，完整包含「审核诊断→分析定位→统一规范→补全缺失→优化提升→链路闭环」全流程能力，所有提示词可直接输入生成式AI执行。

---

## 一、通用前置规范（全场景强制执行）

### 角色锚定

统一设定为：**YYC3集成中心系统 高级UI/UX全链路审核专家**，精通企业级中后台产品交互范式、Tailwind CSS设计系统工程化、Next.js App Router页面规范、iPaaS平台用户心智与操作习惯。

### 输出统一结构

所有提示词输出严格遵循五层结构，确保可落地、可验证、可闭环：

1. ✅ **合规项**：已符合规范的内容清单
2. ⚠️ **问题项**：标注「位置+问题描述+影响等级（低/中/高）」
3. 🔧 **完善/补全方案**：直接可用的代码片段、配置规则或设计规范，禁止空泛描述
4. 💡 **优化建议**：体验提升方向（非强制但推荐）
5. 🔁 **闭环验证点**：修改后必须校验的核心指标，形成闭环

### 边界约束

- 严格遵循项目技术栈，不得引入额外UI组件库，所有样式基于Tailwind CSS v3自定义实现
- 对齐项目五大功能模块（集成中心、AI助手、安全权限、数据同步、管理监控）的业务特性
- 符合企业级产品调性：高效、清晰、低学习成本，禁止过度视觉化与冗余动效
- 满足企业级安全要求：权限可见性、操作二次确认、敏感信息脱敏等

## 二、第一维度：全局UI页面系统层（底座层）

核心目标：统一全项目页面底层规则，实现「百页一面」的系统级一致性

### 1. 全局设计令牌（Design Token）审核·统一·补全提示词

**适用场景**：Tailwind配置审核、全局样式规范统一、设计令牌补全、魔法值清理

```
【任务】对输入的Tailwind配置文件/全局样式代码/页面样式进行全维度设计令牌审核、统一规范与缺失补全，确保全项目视觉语言完全一致。
【输入】{{tailwind.config.ts 配置文件 / 全局样式代码 / 页面组件代码}}
【核心维度】
1. 色彩系统：
   - 主色、辅助色、中性色、功能色（成功/警告/错误/信息）是否完整定义在theme.extend中
   - 是否存在硬编码十六进制颜色值、未复用令牌的魔法色值
   - 色阶是否完整（50-900），是否适配明暗双主题
   - 功能色是否与业务状态一一对应（集成运行中、同步失败、操作成功等）
2. 字号与行高：
   - 是否遵循统一的字号体系（xs/sm/base/lg/xl/2xl...），是否存在自定义px字号
   - 行高、字重是否与字号配对统一，标题、正文、辅助文字层级是否清晰
3. 间距与布局：
   - 是否基于统一间距刻度（0.5/1/2/3/4/6/8...），是否存在零散边距值
   - 容器宽度、页面内边距、模块间距是否全局统一
4. 圆角与阴影：
   - 圆角等级（sm/base/lg/xl/full）是否统一，组件圆角是否匹配其层级
   - 阴影层级（sm/base/lg/xl）是否规范，是否存在自定义阴影值
5. 边框与分割线：
   - 边框颜色、粗细、样式是否统一，分割线是否复用全局令牌
【输出要求】严格遵循通用五层输出结构，补全方案需给出可直接复制的tailwind.config.ts配置片段，问题项需标注具体的类名/属性值。
【约束】所有设计令牌必须在Tailwind主题中统一定义，禁止组件内硬编码基础样式。
```

### 2. 全局页面架构与布局体系审核·补全·规范提示词

**适用场景**：页面结构评审、布局组件开发、新页面搭建规范校验

```
【任务】对输入的页面文件/布局组件进行全局架构一致性审核，补全缺失的布局模块，统一全项目页面骨架。
【输入】{{layout.tsx / page.tsx / 页面组件代码 / 页面设计稿}}
【核心维度】
1. 整体布局框架：
   - 是否严格遵循「顶部全局导航+左侧功能菜单+主内容区」的标准后台布局
   - 侧边菜单折叠/展开状态是否全局统一，是否有记忆功能
   - 内容区最大宽度、左右内边距是否全局一致
2. 页面头部规范：
   - 是否包含「面包屑+页面标题+操作区」的标准头部结构
   - 面包屑层级是否正确，页面标题层级是否统一
   - 主操作按钮、次要操作按钮的位置与排序是否符合规范
3. 内容区结构：
   - 卡片、表格、表单等内容容器的边距、间距是否统一
   - 多模块页面的模块分割、标题层级是否清晰
4. 底部与固定层：
   - 表单页底部操作栏是否固定、是否统一
   - 弹窗、抽屉的位置、遮罩、关闭逻辑是否全局一致
5. 响应式适配：
   - 不同屏幕宽度下的布局降级是否合理
   - 侧边栏、表格、表单的响应式行为是否统一
【输出要求】通用五层结构，补全方案需给出标准布局组件的TSX代码片段。
【约束】所有页面必须复用全局布局组件，禁止单独编写页面骨架。
```

### 3. 基础组件库一致性审核·完善·优化提示词

**适用场景**：基础组件评审、组件代码审核、组件状态补全

```
【任务】对输入的基础组件（按钮、表单、表格、弹窗、分页、标签、提示等）进行规范性审核，完善缺失状态与交互，统一全项目组件表现。
【输入】{{组件代码 / 组件设计稿 / 组件使用示例}}
【核心维度】

2. 样式一致性：
   - 是否完全复用全局设计令牌，是否存在组件内自定义样式
   - 同类型组件的尺寸、间距、圆角、阴影是否全局统一
3. 交互统一性：
   -  hover、点击、禁用的交互反馈是否一致
   - 组件的光标样式、聚焦状态、键盘导航是否符合规范
4. 可复用性：
   - Props定义是否完整，是否支持自定义扩展
   - 是否硬编码业务逻辑，是否具备纯组件通用性
5. 类型安全：
   - 是否有完整的TypeScript类型定义，是否存在any类型
   - 事件、属性的类型是否与项目规范一致
【输出要求】通用五层结构，完善方案需给出修正后的组件完整代码。
【约束】所有业务页面必须复用基础组件，禁止重复实现通用能力。
```

### 4. 路由与页面元数据规范审核·统一提示词

**适用场景**：新增页面路由、页面元数据配置、权限守卫校验

```
【任务】对输入的路由文件、页面配置进行规范审核，统一全项目路由命名、元数据与权限逻辑。
【输入】{{app目录下的路由结构 / page.tsx元数据配置 / 路由守卫代码}}
【核心维度】
1. 路由命名规范：

   - 动态路由、嵌套路由的层级是否合理，是否存在过深嵌套
2. 页面元数据：
   - 是否配置统一格式的title、description，是否符合「页面名 - YanYuCloudCube集成中心」规范

3. 路由权限：
   - 是否配置对应路由的权限守卫，是否与全局权限体系打通
   - 无权限跳转、登录过期跳转逻辑是否统一
4. 导航与激活态：
   - 侧边菜单激活态是否与路由准确匹配
   - 面包屑路径是否与路由层级一一对应
【输出要求】通用五层结构，补全方案需给出标准页面元数据与路由守卫代码示例。
```

## 三、第二维度：视觉交互层（感知层）

核心目标：统一全项目视觉反馈规则，打造清晰、高效、可预期的视觉体验

### 1. 全状态视觉规范审核·补全·统一提示词

```
【任务】对输入的页面/组件进行全状态视觉审核，补全缺失状态，统一所有业务场景的状态视觉表现。

```

### 3. 全局动效体系审核·统一·规范提示词

**适用场景**：动效设计评审、过渡动画统一、加载动效规范

```
【任务】对输入的页面/组件动效进行规范性审核，统一全项目动效曲线、时长与适用场景，打造克制专业的企业级动效体验。
【输入】{{动效代码 / 组件动画 / 页面过渡效果}}
【核心维度】
1. 动效规范统一性：
   - 过渡曲线、时长是否全局统一，是否存在突兀的动效参数
   - 不同组件的同类动效（弹窗出现、抽屉滑入、页面切换）表现是否一致
2. 动效合理性：
   - 动效是否服务于功能，是否存在无意义的装饰性动效
   - 动效时长是否控制在合理范围（150-300ms），是否影响操作效率
3. 加载动效：
   - 全局加载、局部加载、骨架屏的使用场景是否清晰区分
   - 加载动效的视觉样式、位置是否统一
4. 反馈动效：
   - 操作点击、状态切换的反馈动效是否一致
   - 是否存在动效缺失或过度动效的问题
【输出要求】通用五层结构，统一方案需给出全局动效配置代码与使用规范。
【约束】禁止使用影响性能的复杂动效，所有动效必须基于CSS Transition/Transform实现。
```

【任务】对输入的表单页面/组件进行交互逻辑审核，优化输入体验，完善校验与引导机制。

【核心维度】
1. 输入校验：

   - 错误提示位置、样式、文案是否统一，是否清晰说明错误原因与修正方式
2. 输入辅助：
   - 是否有输入提示、占位符、格式说明
   - 长表单是否有必填标识、输入长度限制、字数统计
3. 操作逻辑：
   - 保存、保存并新增、取消、重置的按钮排序与逻辑是否统一
   - 未保存离开是否有提示确认
4. 表单布局：
   - 表单项排序、分组是否符合用户填写习惯

   - 复杂表单是否有步骤引导、进度提示

## 五、全链路闭环验收层（闭环管控）

核心目标：从设计到交付全链路校验，形成「评审→修改→验证→验收」的完整质量闭环

### 1. 设计还原度走查闭环审核提示词

**适用场景**：开发完成后UI走查，校验设计稿与实现稿的一致性

```
【任务】基于设计稿对最终实现的页面进行1:1还原度走查审核，输出差异清单与修正方案，验证通过后形成走查闭环。
【输入】{{UI设计稿}} + {{实现页面代码/截图}}
【核心维度】
1. 尺寸间距：边距、字号、组件尺寸与设计稿的偏差是否在允许范围内
2. 颜色样式：色彩、透明度、阴影、圆角与设计稿是否一致
3. 布局结构：页面布局、模块顺序、元素位置与设计稿是否匹配
4. 图标素材：图标、插画、图片的样式、尺寸、位置是否正确
5. 状态表现：所有交互状态与设计稿是否一致
【输出要求】
✅ 还原一致项
⚠️ 差异偏差项（标注偏差位置、偏差值、影响等级）
🔧 修正方案（精确到类名与属性值）
🔁 走查闭环验证：修正后重新校验所有偏差项，全部通过则走查闭环
【约束】核心页面还原度偏差不得超过1px，通用组件必须100%还原。
```

### 2. 端到端交互链路闭环验证提示词

**适用场景**：功能测试阶段，验证完整操作链路的交互一致性与闭环完整性

```
【任务】模拟真实用户操作，对业务功能进行端到端全链路交互验证，确保从入口到出口的完整交互闭环符合规范。
【输入】{{功能模块 / 业务场景 / 操作路径}}
【核心维度】
1. 入口到出口的完整流程是否顺畅，是否存在断点
2. 每一步操作的反馈是否及时、明确、可预期
3. 异常分支、边界场景的交互是否完整
4. 操作完成后是否回到合理的页面，状态是否同步更新
5. 全程操作逻辑、视觉表现是否符合全局规范
【输出要求】
✅ 闭环通过项
⚠️ 链路断点项（标注位置、现象、影响）
🔧 修复方案
🔁 闭环验证：重新走通全链路，无断点则交互闭环通过
```

### 3. 全量UX一致性验收闭环提示词

**适用场景**：版本上线前，全页面全功能的UX一致性最终验收

```
【任务】对整个版本的所有页面与功能进行全维度UX一致性验收，覆盖页面系统、视觉交互、操作逻辑三大维度，形成最终验收闭环。
【输入】{{版本所有页面列表 / 功能模块清单}}
【核心维度】
1. 全局页面系统一致性：布局、组件、路由、元数据是否全部符合规范
2. 视觉交互一致性：状态、动效、异常、信息层级是否全部统一
3. 操作逻辑一致性：通用操作、反馈链路、表单、容错是否全部符合规则
4. 业务场景适配性：五大核心模块的交互是否贴合业务场景，无体验断点
5. 无障碍与易用性：键盘导航、对比度、操作效率是否达标
【输出要求】
✅ 验收通过项
⚠️ 待整改项（分优先级）
🔴 阻断项（必须修复才能上线）
📋 最终验收结论（通过/整改后再审）
🔁 验收闭环：所有阻断项与高优先级问题修复完成，重新验证通过则验收闭环
```

### 4. 迭代优化闭环输入提示词

**适用场景**：基于用户反馈/问题数据进行体验迭代，形成优化闭环

```
【任务】基于输入的用户反馈、问题数据、体验痛点，输出针对性的UI/UX优化方案，并明确验证指标，形成「问题输入→优化方案→效果验证」的迭代闭环。
【输入】{{用户反馈 / 问题数据 / 体验痛点 / 业务需求}}
【核心维度】
1. 问题根因分析：定位体验问题的本质原因（设计不合理/逻辑不顺畅/视觉不清晰）

3. 方案一致性校验：优化方案是否符合全局UI/UX规范，是否破坏统一性

【输出要求】
🔍 问题根因分析
💡 优化方案（分点说明，可直接落地）
✅ 规范符合性校验
📊 验证指标与验收标准
🔁 迭代闭环：优化上线后根据验证指标评估效果，达标则迭代闭环
```
