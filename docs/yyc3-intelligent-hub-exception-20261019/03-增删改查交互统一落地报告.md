## 二、统一方案落地

### 2.1 ConfirmActionDialog —— 确认弹窗组件化（规范 2/3 落地）

新增 [confirm-action-dialog.tsx](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/app/components/ui/confirm-action-dialog.tsx)，四段固定结构业务零自由度：

```
标题：确认{操作}？（批量场景必须含 {count}）
描述：后果说明 +「此操作无法撤销」
[取消（左，AlertDialogCancel）] [确认（右，AlertDialogAction）]
```

支持**触发器模式**（trigger prop）与**受控模式**（open/onOpenChange，先校验后弹窗）；取消/确认文案由调用点经 i18n 显式传入（取消隐藏命名空间查找）。

**四处手写 AlertDialog 全部收敛**：

| 场景 | 模式 | 文件 |
| ---- | ---- | ---- |
| 清空收藏 | 受控 | [favorites/page.tsx](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/app/favorites/page.tsx) |
| 批量删除收藏（{count}） | 受控 | 同上 |
| 取消订阅 | 触发器 | [subscriptions/page.tsx](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/app/account/subscriptions/page.tsx) |
| 禁用加密 | 受控 | [encryption/page.tsx](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/app/account/encryption/page.tsx) |

组件化后 DOM 角色（alertdialog/title/description/button）与原实现一致，既有业务测试断言零破坏。

### 2.2 反馈缺陷修复

| 修复 | 实现 |
| ---- | ---- |
| 双 toast 去重 | sync 页 handleSync 仅 `await syncWithCloud()`，反馈唯一出口为 context 层；删除页面 useToast 死代码 |
| 卡片删除反馈 | handleRemove 补 toast（复用 FavoriteButton 同款文案键 `favorites.已从收藏中移除`，同类操作反馈措辞完全一致） |

### 2.3 context 层 i18n 收敛（11 条 toast → t()）

- **favorites-context**：引入 useI18n（provider 内），7 条同步/保存 toast 全部转换，复用既有 `account.同步成功/同步失败/您的收藏已成功同步到云端` 键，新增 8 键；两个 useCallback 依赖数组补 `t`
- **subscription-context**：4 条取消订阅/设置更新 toast 转换，错误描述统一走既有 `common.发生错误，请稍后重试`，消除同文件 subscribe（t()）与 unsubscribe（硬编码）的混用割裂

### 2.4 i18n 键补充（account 命名空间，中英双语）

新增 14 键：保存失败 / 无法保存收藏数据 / 请先登录以使用云同步功能 / 您的收藏已成功加密并同步到云端 / 加密同步失败，请稍后重试 / 无法同步到云端，请稍后重试 / 发现冲突 / 本地数据与云端数据存在冲突，请手动解决 / 取消订阅成功 / 您已取消订阅{name} / 取消订阅失败 / 设置已更新 / 订阅设置已成功更新 / 更新设置失败（[zh-CN.ts](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/lib/yyc3/i18n/messages/zh-CN.ts) / [en.ts](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/lib/yyc3/i18n/messages/en.ts)）

## 三、增删改查交互规范（终版禁令，增补第 13-15 条）

> 承接 01 报告 1-8 条与 02 报告 9-12 条：

13. **危险操作确认只准用 `ConfirmActionDialog`**（四段固定结构），禁止手写 AlertDialog 组合；反馈唯一性原则：同一写操作的 toast 只允许一层发起（context 发起则页面不重复）
14. **同一类写操作的反馈文案必须复用同一 i18n 键**（如卡片删除与心形按钮移除共用「已从收藏中移除」），禁止同义异形
15. **context 层反馈必须走 useI18n**，禁止硬编码中文；新增业务 context 时在 provider 内注入 `const { t } = useI18n()` 并纳入 useCallback 依赖
