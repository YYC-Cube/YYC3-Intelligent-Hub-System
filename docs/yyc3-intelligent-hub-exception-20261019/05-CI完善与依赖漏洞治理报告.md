### 排障记录（环境陷阱）

| 现象 | 根因 | 处置 |
| ---- | ---- | ---- |
| `pnpm audit` 报 "packages field missing or empty" | 单仓项目 pnpm-workspace.yaml 缺 packages 字段 | 补 `packages: ['.']` |
| `ERR_PNPM_AUDIT_ENDPOINT_NOT_EXISTS` | 本地镜像源 npmmirror 无 audit 端点 | `--registry=https://registry.npmjs.org`（CI 默认官方源不受影响） |
| auditConfig 豁免本地不生效 | 本地 pnpm 9.15.4 不读 workspace yaml 的 auditConfig/overrides（pnpm 10 特性），且 pnpm 9 install 曾把 lockfile 降级 | 统一用 `npx pnpm@10` 对齐 CI 版本重新生成 |
| 新终端 PATH 缺失 | nvm 懒加载未初始化 | 手动注入 PATH + nvm source |

## 二、CI 配置完善（[ci-cd.yml](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/.github/workflows/ci-cd.yml)）

| 项 | 变更 | 价值 |
| -- | ---- | ---- |
| typecheck 脚本化 | `npx tsc --noEmit` → `pnpm typecheck`（package.json 新增脚本） | 去除 npx 解析不确定性，本地/CI 同一入口 |
| 全量审计门禁 | 新增 `pnpm audit --audit-level=high`（生产树审计之外覆盖 dev 链） | 阻断新引入的高危传递依赖（历史 sprintf-js 案例即属此类） |
| 并发策略 | `cancel-in-progress: ${{ github.event_name == 'pull_request' }}` | PR 新提交取消旧运行省额度；main 串行部署不取消 |

最终门禁链：install(--frozen-lockfile) → lint → typecheck → test → audit(--prod) → audit(full) → build → deploy。

## 四、维护规范

1. **依赖治理双通道**：有修复版的传递依赖走 `pnpm-workspace.yaml overrides` 强制提升；无修复版的构建期依赖走 `auditConfig.ignoreGhsas` 豁免并强制注明 GHSA/暴露面依据与复核日期
2. **本地必须对齐 CI 的 pnpm 10**（`npx pnpm@10`）：pnpm 9 会静默忽略 workspace yaml 配置并可能降级 lockfile
3. 构建期工具（postcss/tailwind 插件族）一律放 devDependencies——静态导出项目生产树只保留运行时真依赖
