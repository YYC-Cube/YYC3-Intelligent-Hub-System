| /marketplace/category/[category] | 子分类 Tab / 排序 | 🔴 **跨类别导航页码残留**（Bug 2）+ **排序切换页码残留**（Bug 3） |
| /favorites | 搜索 / 类别 / 排序 | ✅ 无分页（全量渲染），不涉及 |

### 三个页码 Bug 的共同根因

> 显式 `setCurrentPage(1)` 依赖**每个事件 handler 记得调用**，而 URL 参数变化（router.push 新搜索）与动态路由段导航（复用组件实例）**根本没有本地 handler**——事件驱动模式天然覆盖不了状态驱动的筛选来源。

## 二、统一方案：useFilterPage 组件化基建

### 2.1 核心 Hook（[use-filter-page.ts](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/app/hooks/use-filter-page.ts)）

```tsx
const [currentPage, setCurrentPage] = useFilterPage([
  query, categoryParam, sortBy, /* ...全部筛选依赖 */
]);
```

- **渲染期调整状态模式**（React 官方推荐，替代 effect 副作用）：同步重置、无闪帧、无额外渲染轮次
- 逐元素 `Object.is` 比对（数组每轮新建不影响判定；NaN 场景正确视为相等）
- **天然覆盖三类筛选来源**：本地 state / URL 参数 / 父组件 props —— 事件驱动漏网问题根治

### 2.2 四个分页消费方全部接入（显式重置全部移除）

## 三、FilterSidebar 三项修复（[filter-sidebar.tsx](file:///Users/yanyu/YYC-Cube/YYC3-Intelligent-Hub-System/app/marketplace/components/filter-sidebar.tsx)）

| 问题 | 严重度 | 修复 |
| ---- | ------ | ---- |
| **应用筛选丢失搜索词 q**（重建 URL 未携带，搜"CRM"后应用筛选 → 关键词被清空） | 🔴 高 | `buildParams()` 统一保留 `q` |
| 无「清空筛选」入口（list-client 有重置，此处没有，违反重置规范） | ⚠️ 中 | 补 `clearFilters`（outline 次级按钮，与「应用筛选」右对齐成组），跳转仅保留 q 的结果页 |
| 打开面板不回显已应用条件（勾选了类别 A，面板显示全空） | ⚠️ 中 | `useState` 惰性初始化从 `useSearchParams` 回读（面板条件渲染，每次打开即回读最新 URL） |

**统一后的筛选面板交互闭环**：打开回显 → 调整 → 清空（可选）→ 应用（保留 q）→ URL 变化 → useFilterPage 自动回第 1 页。

## 五、更新后的搜索与筛选交互规范（增补第 9-12 条）

> 承接 01 报告 8 条禁令，本阶段增补：

9. **页码重置只准用 `useFilterPage`**，deps 必须罗列全部筛选依赖（含路由参数与数据源 props）；业务代码禁止出现 `setCurrentPage(1)` 散写
