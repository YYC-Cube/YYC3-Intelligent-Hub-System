## 一、严重阻断问题（BLOCKER，禁止流入下一阶段）

### B-1 收藏页「删除所选」为空实现（功能欺骗）

- **问题位置**：[app/favorites/page.tsx](../../app/favorites/page.tsx#L104-L112)
- **风险等级**：严重（P0）
- **违反规范**：业务真实性 / 事件维度（Event：用户操作无对应状态变更）
- **事实**：`handleDeleteSelected` 仅弹出 Toast 与清空选中项，**从未调用** context 的 `removeFavorite`。注释亦自认（"这里实际上会通过context中的removeFavorite方法逐个删除"）。
- **影响**：用户认为已删除，实际数据仍在 `localStorage`；刷新后"复活"，属数据一致性事故。
- **修复建议**：改为 `selectedItems.forEach(removeFavorite)`；补充 vitest 用例断言存储键内容同步变化。

### B-2 核心基座（MCP / Skill 沙箱 / 持久化抽象）为未接线死代码

- **问题位置**：[lib/yyc3/mcp/*](../../lib/yyc3/mcp/types.ts)、[lib/yyc3/sandbox/*](../../lib/yyc3/sandbox/policy.ts)、[lib/yyc3/store/*](../../lib/yyc3/store/index.ts)
- **风险等级**：严重（P0，架构级）
- **违反规范**：五高架构（High Availability / Scalability）；基座规范落地
- **事实**：全仓 `grep "@/lib/yyc3/(store|mcp|sandbox)"` 仅命中**注释与 i18n/brand**，业务代码（`app/**`）对上述三模块**零引用**；`@yyc3/core`（`package.json` L92）同样零 import。即：协议契约、沙箱策略、三层适配器均已写好但**未接入任何调用链**，无法验证"沙箱隔离已启用""MCP 调用合规"。
- **影响**：任务书要求的"沙箱隔离启用""MCP 协议合规""store 抽象层收口"当前**不成立**，只能算"已备未用"。
- **修复建议**：阶段 3 建立唯一调用入口（如 `app/services/hub/hub-runtime.ts`）接线；或在报告中明示降级为"能力预留"，避免虚假合规。

### B-3 持久化契约"双源"，`@yyc3/store` 未真正承担抽象层职责

- **问题位置**：[app/services/storage/local-storage-store.ts](../../app/services/storage/local-storage-store.ts#L21)、[lib/yyc3/store/types.ts](../../lib/yyc3/store/types.ts#L58)
- **风险等级**：严重（P0）
- **违反规范**：禁止直接硬编码读写；统一抽象层
- **事实**：仓库存在**两套并行 `Store` 契约**——npm 包 `@yyc3/store`（仅 `import type` 使用）与自研 `@/lib/yyc3/store/types`（未被业务引用）。真实读写落在 `LocalStorageStore`，其 `getSync/putSync/deleteSync` 为自研同步内核；键名 `favorites`、`favorites_${user.id}`、`favorites_encrypted_${user.id}` **在各调用处以字符串字面量硬编码**，未走 [lib/yyc3/store/keys.ts](../../lib/yyc3/store/keys.ts) 的 `scopedKeys` 注册。
- **影响**：契约漂移；键名冲突与迁移风险；"三层适配器可替换"承诺无法兑现。
- **修复建议**：统一以 `@/lib/yyc3/store` 为唯一契约；键名集中注册；`LocalStorageStore` 收敛为其 browser 适配器（其 `app/services` 位置亦应迁入 `lib/yyc3/store`）。

## 二、高危缺陷（HIGH）

### H-1 应用市场存在两套并行实现，卡片能力与分页规格冲突

- **问题位置**：[app/integrations/page.tsx](../../app/integrations/page.tsx#L22)（30/页 → 34 页）vs [app/marketplace/components/integration-browser.tsx](../../app/marketplace/components/integration-browser.tsx#L77)（12/页 → 84 页）
- **风险等级**：高
- **违反规范**：五化（标准化/归一化）；组件复用；DRY
- **事实**：两套路由各自实现检索/筛选/分页/卡片：
  - `/integrations`：30/页、共 **34 页**、含分类记忆与 `useOptimizedFilter`、jest+vitest 覆盖充分，但卡片**无编号、无收藏、无评分**；
  - `/marketplace`：12/页、共 **84 页**、卡片含**编号 + 分类标签 + 简介 + 评分 + 收藏 + 价格**，但测试薄弱。
  任务书同时要求"卡片含编号/分类标签/方案简介"与"分页共 34 页"，**当前无任何一个实现同时满足**。
- **修复建议**：以 `/integrations` 为数据与筛选内核、以 `/marketplace/components/integration-card.tsx` 为卡片呈现基准，做"统一数据层 + 单一卡片组件"收敛（属**兼容增强**，保留两条路由只做复用改造）。

### H-2 收藏按钮仅 hover 可见：触屏/键盘不可达 + 与"新上线"徽标重叠

- **问题位置**：[app/marketplace/components/integration-card.tsx](../../app/marketplace/components/integration-card.tsx#L33)（新上线 Badge，`top-2 right-2`）与 [同文件 L95-L99](../../app/marketplace/components/integration-card.tsx#L95-L99)（收藏按钮，同为 `top-2 right-2`，条件 `isHovering`）
- **风险等级**：高
- **违反规范**：WCAG 2.1（可操作性/焦点可见）；UI 一致性
- **事实**：`isHovering` 由 framer-motion `onHoverStart/End` 驱动，**触屏与纯键盘无 hover 事件**；两元素定位完全重合，hover 时收藏按钮以 `z-10` 覆盖 Green Badge。
- **修复建议**：收藏按钮改为常驻（卡片右下或右上独立区），或改用 `group-hover` + `focus-visible` 双通道；为 Badge 与按钮分配互斥定位。

### H-3 搜索结果页分页"全量展开"，与窗口化分页不一致

- **问题位置**：[app/marketplace/search/page.tsx](../../app/marketplace/search/page.tsx#L247)
- **风险等级**：高
- **违反规范**：High Performance；五化（自动化/可视化一致性）
- **事实**：`Array.from({ length: totalPages })` 全量渲染页码，1000 条 → **84 个按钮**；而 `IntegrationBrowser` 已实现窗口化 `buildPageWindow`（[L50-L61](../../app/marketplace/components/integration-browser.tsx#L50-L61)）。同一产品内两套分页交互。
- **修复建议**：抽出 `Pagination` 公共组件（`app/integrations/components/Pagination` 已存在，可直接复用），搜索页接入窗口化逻辑；为 84 页场景补边界用例。

### H-4 收藏按钮文案硬编码，绕过 i18n

- **问题位置**：[app/components/favorites/favorite-button.tsx](../../app/components/favorites/favorite-button.tsx#L37-L39)
- **风险等级**：高
- **违反规范**：i18n 规范化（同仓其余组件均走 `lib/yyc3/i18n`）
- **事实**：`"已从收藏中移除"/"已添加到收藏"/"该集成应用已从您的收藏列表中移除"` 为字面量，未走 `t()`；与 [app/favorites/page.tsx](../../app/favorites/page.tsx#L107) 使用 `t("favorites.…")` 的做法不一致。
- **修复建议**：迁入 `favorites.*` 词条；补 en 文案与快照测试。

### H-5 依赖声明与实际引用不一致（`@yyc3/core`、`@yyc3/store` 值导入被刻意阻断）

- **问题位置**：[package.json](../../package.json#L92-L94) vs [app/services/storage/local-storage-store.ts](../../app/services/storage/local-storage-store.ts#L16-L18)
- **风险等级**：高
- **违反规范**：TreeShaking / 零额外运行时依赖
- **事实**：源码注释明确说明 `@yyc3/store` 入口因 **硬依赖 ioredis（Node-only）** 会污染浏览器 bundle，故 `putJson/getJson` 为本地重实现、只用 `import type`。这解释了 B-3 的成因，但意味着**声明的依赖实际无法在客户端使用**。
- **修复建议**：向 `@yyc3/store` 提出**子路径导出**（如 `@yyc3/store/browser`）以恢复单一契约；仓库侧保留本地重实现并加 `// WHY:` 说明与过期检测。

### H-6 价格筛选上限与数据分布不匹配

- **问题位置**：[app/data/integrations.ts](../../app/data/integrations.ts#L1088)（`priceValue ∈ [10,109]`）vs [app/marketplace/components/filter-sidebar.tsx](../../app/marketplace/components/filter-sidebar.tsx#L119)（滑块 `max={100}`）
- **风险等级**：高（功能不可达）
- **违反规范**：业务对齐；边界完整性
- **事实**：付费应用价格可达 109，而最大可筛选值为 100，`¥100–109` 区间**无法被表达**；搜索页默认 `maxPrice=100`（[search/page.tsx L33](../../app/marketplace/search/page.tsx#L33)）使 `maxPrice < 100` 恒假，价格区间筛选在"未显式设置"时静默失效。
- **修复建议**：滑块上限提升至 `120`（或取数据集动态 `max`）；补"区间边界含端点"的边界用例。

### 迁移关键陷阱（复用价值）

1. **TS1109 解析错误**：`(cond ? describe : describe.skip,) as typeof describe` 多行尾逗号结构，错误行号随编辑漂移；改闭括号紧跟表达式即解。
2. **vi.spyOn × restoreMocks 冲突**：vitest 全局 `restoreMocks` 在 before each 恢复 spy，导致 spyOn 后 mockReturnValue 拦截失效（读值回退而非报错，隐蔽性强）；解法为文件内显式整体替换 Storage，等价原 jest.setup 全局 mock 语义。
3. **vitest include 盲区**：jest 全仓 testMatch 会接管 `app/services/ai/tests/` 等散落测试，vitest include 收敛到 `tests/**` 后形成盲区——迁移时必须 Glob 全仓 `*.test.{ts,tsx}` 兜底（本次发现第 7 个文件 ensemble-engine）。
4. **源码守卫测试路径耦合**：TC-U-030 直接 readFileSync 单文件路径，模块目录化后需改 readdirSync 扫描。
