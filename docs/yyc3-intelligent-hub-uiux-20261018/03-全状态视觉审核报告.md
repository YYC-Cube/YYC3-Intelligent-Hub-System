## Layer 3 · 补全方案（状态样式类名速查）

### 3.1 通用组件六件套 · 状态类名规范

**Button**（[button.tsx](../../../components/ui/button.tsx)）——按下态全变体统一：

```txt
按下    active:scale-[0.98] active:disabled:scale-100
过渡    transition-[color,background-color,border-color,box-shadow,transform]
```

**Input / Textarea**（状态链：默认→hover→focus→错误；read-only ≠ disabled）：

```txt
悬浮    hover:border-ring/60
只读    read-only:cursor-default read-only:bg-muted/50 read-only:hover:border-input
错误    aria-invalid:border-destructive aria-invalid:hover:border-destructive
        aria-invalid:focus-visible:border-destructive aria-invalid:focus-visible:ring-destructive
禁用    disabled:cursor-not-allowed disabled:opacity-50 disabled:hover:border-input
```

**Select**（开启态增强 + 箭头旋转）：

```txt
悬浮    hover:border-ring/60 hover:bg-accent/30
开启    data-[state=open]:border-ring
箭头    [&>svg]:transition-transform [&[data-state=open]>svg]:rotate-180
```

**Checkbox**（半选态一等公民）：

```txt
半选    data-[state=indeterminate]:border-primary data-[state=indeterminate]:bg-primary
        data-[state=indeterminate]:text-primary-foreground
图标    Check/Minus 双图标按父级 data-state 任意变体切换（[[data-state=indeterminate]>&]）
悬浮    hover:border-ring hover:bg-primary/10（选中态 hover 不褪色：data-[state=checked]:hover:bg-primary）
```

**Switch / RadioGroup / Tabs**（hover 链路闭合）：

```txt
Switch     data-[state=unchecked]:hover:bg-input/70 data-[state=checked]:hover:bg-primary/90
RadioGroup hover:border-ring hover:bg-primary/10 data-[state=checked]:border-primary
TabsTrigger hover:text-foreground data-[state=active]:hover:text-foreground
```

**CustomTabs**（抖动修复——边框宽度恒定，颜色表达激活）：

```txt
激活    border border-primary bg-card text-foreground
非激活  border border-transparent bg-muted text-muted-foreground hover:text-foreground
```

### 3.2 业务数据状态 · 四态规格

| 数据态 | 组件 | 规范类名/用法 |
| --- | --- | --- |
| 加载中（路由级） | `RouteSkeleton` | `<RouteSkeleton />` 网格布局 / `variant="detail"` 详情布局；`role="status" aria-busy="true"` |
| 加载中（块级） | `Spinner` / Skeleton | `<Spinner size="medium" />`；骨架 `animate-pulse bg-muted` |
| 空 | `EmptyState` | `<EmptyState icon title description actions size="sm"\|"default" />` 四段式；`role="status"` |
| 有数据 | 业务网格 | 直接渲染，禁止包裹多余状态容器 |
| 加载失败 | `ErrorDisplay` | destructive 卡片 + 重试主按钮（反馈强度最高档） |

### 3.3 操作结果状态 · 四色统一入口

```ts
import { toastSuccess, toastWarning, toastError, toastInfo } from "@/hooks/use-toast"

toastSuccess("已保存")            // success 绿：操作达成
toastWarning("即将超出配额")      // warning 黄：可恢复风险
toastError("同步失败")            // destructive 红：操作失败（Toast/Alert/Badge/Button 同名变体）
toastInfo("新版本可用")           // info 蓝：中性告知
```

**反馈强度匹配律**：破坏性操作错误 → Toast(destructive) + 操作区重试；页面级崩溃 → ErrorDisplay 卡片；瞬时确认 → toastSuccess。禁止用 info 表达失败。

### 3.4 选中与激活状态 · 权重规范

| 场景 | 激活样式 | 权重依据 |
| --- | --- | --- |
| 表格行选中 | `data-[state=selected]:bg-muted`（[table.tsx](../../../components/ui/table.tsx)） | 悬浮 /50、选中全量，两级可辨 |
| 命令面板高亮 | `data-[selected=true]:bg-accent text-accent-foreground` | Radix 惯例 |
| 标签激活 | Tabs `bg-background shadow-sm`；CustomTabs `border-primary bg-card` | 面上浮 = 激活 |
| 多选选中 | Checkbox `bg-primary` 实底白勾 | 实底 = 确定态 |
| 单选选中 | RadioGroup `fill-current` 内圆 + `border-primary` 加深 | 双标识冗余强化 |
| 业务运行态 | `<Badge variant={statusVariant(status)} />`（映射表见 3.5） | 色彩即语义 |

### 3.5 业务状态 → 视觉语义映射表（唯一真源）

**位置**：[status-variants.ts](../../../lib/yyc3/status-variants.ts)

```txt
success      运行中 / 已同步 / 已完成        （稳定正向）
info         同步中 / 处理中 / 搜索中        （动态进行中，与 success 的区别：过程未完成）
warning      未同步 / 冲突 / 即将到期        （待人工介入）
destructive  失败 / 异常 / 校验错误          （失败态）
secondary    已停止 / 未启用                 （中性停用，禁止误用 destructive）
未知状态      一律兜底 warning（statusVariant() 内建）
```

## Layer 4 · 使用规范（业务接入三律）

1. **取色一律走语义层**：业务代码禁止内联 `bg-success/15` 拼类，状态展示用 `<Badge variant={statusVariant("running")} />`，操作反馈用 `toastSuccess/Error/...`，进度用 `<Progress variant="success" />`。
2. **四态必须齐备**：任何数据视图（列表/卡片/详情）上线前自检「加载中 / 空 / 有数据 / 失败」四态，空态一律 `EmptyState`，路由级加载一律 `RouteSkeleton`。
3. **状态链完整自检**：交互组件按「默认→悬浮→按下/开启→禁用→错误」人工走查一遍；禁用态策略二分法不变（按钮 `pointer-events-none`、输入型 `cursor-not-allowed`）。

## 英文环境抽查执行结果（2026-10-19 三次更新）

按 [04-英文环境抽查清单](./04-英文环境抽查清单.md) 完成 Playwright 自动化走查（14 路由 + C1-C8 交互断言）。执行过程中发现并修复 **2 个 P0 存量缺陷**（均与本轮 UI/UX 改造无关，属抽查顺带挖出的深层问题）：

### 发现一：/integrations 双语白屏级死循环（P0，存量）

- **现象**：`/integrations` 任意语言下页面崩溃进 ErrorDisplay（"Maximum update depth exceeded"），首跑交互断言超时由此引起。
- **定位**：React 组件栈捕获锁定 `forceStoreRerender` / `updateStoreInstance`——`CollapsibleCategoryFilter` 的 effect 内调用 `CategoryMemoryService.saveExpandedState`（每次写入 `lastVisited: Date.now()`）→ `useClientSnapshot` 快照 JSON 变化 → `useSyncExternalStore` 强制重渲染 → effect 重跑 → 无限循环。对比实验证实 zh-CN/en 双语皆崩，与 i18n 无关。
- **修复**：持久化移入 `toggleCategory` 用户交互路径；effect 仅保留对父组件的通知。详见 [CollapsibleCategoryFilter.tsx](../../../app/integrations/components/CollapsibleCategoryFilter.tsx#L184-L199)。

### 发现二：i18n 引擎键内点号切碎缺陷（P0，引擎级，应用层兼容层修复）

- **现象**：含 ASCII 点的键（省略号 `...`、句点，如「搜索应用...」「© ... 保留所有权利.」）在任何语言下查键必失败、恒回退中文；不含点的键（如「账户」）正常。
- **根因**：`@yyc3/i18n-core` v3.0.2 `resolveTranslation` 以 `key.split(".")` 逐段下钻注册表，键内 ASCII 点被误当作命名空间分隔符切碎。
- **修复**：`lib/yyc3/i18n/index.ts` 应用层兼容层——词表注册与 `t()`/`tc()` 入口同规则变换（前导 ASCII ns 段保留，其后所有 ASCII 点→全角 `．`、`...`→`…`），调用点与词表文件零侵入；`use-i18n` 封堵绕行入口。
- **回归锁定**：新增 [tests/i18n-key-normalization.test.ts](../../../tests/i18n-key-normalization.test.ts)（6 例：点号键双语、数据层词表、学习路径/版本历史 tc 动态键）。
