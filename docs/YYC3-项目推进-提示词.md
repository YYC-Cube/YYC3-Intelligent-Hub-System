# 核心任务链路（必须按顺序闭环执行，每阶段输出结构化报告，上一阶段问题必须流入下一阶段修复验证）
链路顺序：【1.全局审核 → 2.全维度测试 →3.代码/业务补全 →4.产品&架构完善 →5.前沿新技术同步集成 →6.回归复测，闭环归档】

## 阶段1：全局审核（架构、业务、UI、安全、代码规范五维审核）
输入材料：源码片段 / 前端页面需求 / 新增应用集成卡片 / API接口
审核维度：
1.业务对齐：是否匹配言语云应用市场页面的分类体系、应用卡片数据结构、字段规范；分类标签、应用描述、编号字段是否与当前页面结构一致，不存在业务冲突。
2.架构审核：是否遵守YYC3基座规范，MCP协议调用是否合规；沙箱隔离是否启用；持久化存储是否使用@yyc3/store抽象层，禁止直接硬编码读写Redis/文件；模块职责是否解耦，是否符合DDD领域划分；是否满足TreeShaking零运行时依赖约束。
3.代码规范：TS类型完整度；接口类型定义；JSDoc注释；命名规范；导出API是否暴露合理；类型any滥用检测；循环依赖扫描。
4.安全审核：输入净化、沙箱权限隔离、越权访问、注入风险、密钥硬编码、跨域、权限校验；应用连接器第三方API调用风险。
5.UI页面审核：React组件、shadcn/ui组件复用；主题ThemeManager适配；多主题切换；页面列表分页逻辑；卡片渲染、收藏交互、评分展示是否匹配应用市场页面。

输出：《YYC3全局审核报告》，分为【严重阻断问题/高危缺陷/一般优化点/低优先级建议】，每个问题附带：问题位置、风险等级、违反规范、修复建议。阻断问题不允许进入下一环节。

## 阶段2：全维度测试（单元+组件+业务场景+边界+对抗测试）
基于审核通过的代码/需求生成测试体系，基于vitest + testing-library/react
1.单元测试：核心函数、工具类、@yyc3/core调用逻辑、MCP协议解析、store存储适配器；必须覆盖分支，输出覆盖率指标。
2.React组件测试：应用卡片渲染、分页、收藏按钮、分类筛选、搜索筛选、应用列表加载、空状态、加载异常。
3.业务场景测试：新增应用上架、分类检索、收藏/取消收藏、应用详情打开、多分类切换、分页翻页（共34页）。
4.边界测试：应用数量0/超大1000条、分类不存在、非法编号、超长应用描述、特殊字符注入、网络超时、存储读写失败。
5.对抗安全测试：恶意连接器配置、沙箱逃逸尝试、非法MCP指令、越权读取其他用户收藏。

输出：《YYC3测试用例集+测试报告》，包含用例ID、场景、预期结果、实际结果、失败用例根因；失败用例自动标记，流入补全环节。

## 阶段3：代码&业务补全
基于审核缺陷+测试失败用例，自动补全缺失内容：
1.补全TS类型定义、缺失interface、枚举（应用分类枚举、应用卡片数据模型，对齐网页29分类）
2.补全组件逻辑、状态管理、接口请求、异常捕获
3.补全JSDoc注释、缺失vitest单元测试代码
4.补全应用市场卡片数据，新增应用卡片模板严格遵循页面现有格式（编号+分类标签+方案描述）
5.补全错误处理、降级逻辑、空页面兜底

输出：修复后的完整代码片段 + 修改清单，标注变更行，说明修复对应哪个审核/测试缺陷。

## 阶段4：产品&架构完善
在不破坏现有仓库代码和页面业务前提下做优化：
1.应用市场体验优化：检索权重、分类筛选联动、收藏状态持久化、应用评分计算逻辑优化
2.架构优化：MCP调用链路简化、沙箱资源限制调优、store读写性能优化、组件抽离复用
3.数据模型完善：统一应用集成元数据schema，标准化连接器描述，统一分页参数
4.兼容性完善：主题切换、移动端适配、加载性能优化

输出：架构优化方案、产品需求优化清单、可直接落地的代码改造方案，区分【不改动现有逻辑的增强】和【破坏性重构（标记风险）】

## 阶段5：新技术同步集成（前沿技术引入评估+适配改造）
持续扫描AI/集成领域新技术，评估是否接入YYC3系统，严格遵守基座约束，不破坏现有业务：
评估维度：MCP新版本、Agent多智能体框架、低代码连接器、新的持久化方案、前端新特性、安全沙箱升级、大模型工具调用新标准；
步骤：
1.技术适用性评估：是否适配TS+React、@yyc3/core基座，能否兼容现有技能沙箱
2.风险评估：性能、稳定性、安全、升级成本、向后兼容性
3.最小集成方案：优先插件化接入，禁止侵入原有核心代码
4.编写集成Demo、新增测试用例、文档
5.评估是否同步更新应用市场分类，新增对应应用卡片

输出：新技术评估报告、POC最小集成代码、风险清单、上线灰度建议。

## 阶段6：回归闭环归档
全部修改完成后，自动执行回归复测：
1.重跑全部测试用例，验证所有阻断/高危缺陷全部修复
2.验证前端页面渲染，新增内容和原有应用市场页面风格、结构完全统一
3.检查类型、规范、安全再次复核
4.生成版本变更记录，归档全部报告，输出闭环总结
> 若回归出现失败，退回【阶段1审核】重新迭代，直到全部通过，形成闭环。
