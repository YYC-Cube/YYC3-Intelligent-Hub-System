## 1. 严重阻断问题（P0 · 必须清零后方可进入下一环节）

### P0-1 900/1000 应用详情页与安装页 404
- **位置**：`app/integrations/[id]/page.tsx:4`、`app/integrations/[id]/install/page.tsx:4`、`app/marketplace/integration/[id]/page.tsx:4`
- **证据**：
  - `app/data/integrations.ts:1063` → `export const integrations = generateIntegrations(1000)`
  - 三个动态路由均写死 `return Array.from({ length: 100 }, (_, i) => ({ id: String(i + 1) }))`
  - `next.config.mjs` 设置 `output: 'export'`（纯静态导出，无 fallback / 无 ISR）
  - `next build` 输出确认每条动态路由仅生成 100 个路径
- **风险等级**：严重阻断
- **违反规范**：业务约束「1000 个集成应用卡片」；单一数据源原则
- **修复建议**：`generateStaticParams` 改为 `integrations.map(i => ({ id: i.id }))`，由数据源驱动；并抽取共享常量，避免三处重复。

### P0-2 7 处死链路由（源码引用但路由不存在）
- **位置**：`/marketplace/browse`、`/marketplace/popular`、`/account/profile`、`/developer/api`、`/developer/components`、`/privacy`、`/terms`
- **证据**：全量 `href="/..."` 抽取后逐一比对 `app/**/page.tsx`，上述 7 条 MISSING（`/marketplace/browse` 为 `app/page.tsx` 主导航按钮目标）
- **风险等级**：严重阻断
- **违反规范**：导航闭环完整性；静态导出下直接 404
- **修复建议**：补齐 7 个页面，或将入口链接指向已存在路由。

### P0-3 模块级 `Math.random()` 生成数据 → 水合不一致 + 数据不可复现
- **位置**：`app/data/integrations.ts:1008-1063`（`generateIntegrations`）
- **证据**：在模块作用域生成 `id`、`rating`（`Math.random() * 2 + 3`）、`installCount`、随机日期等，模块被 import 即执行；服务端预渲染与浏览器端各执行一次，结果不同
- **风险等级**：严重阻断
- **违反规范**：React SSR/CSR 一致性；「4.0 平均评分」需要稳定可复现
- **修复建议**：改为确定性伪随机（seeded PRNG，如 xorshift + 固定 seed）或静态 JSON 数据源，保证两端结果完全一致。

### P0-4 核心基座约束 0% 落地（@yyc3/core / @yyc3/store / MCP / 沙箱）
- **位置**：全仓库
- **证据**：
  - `package.json` / `tsconfig.json` / 全量源码中 `@yyc3` **零命中**（仅 `package.json:2` 的包名 `yyc3-integration-center` 与 `:21` 的 psql 命令为无关命中）
  - `mcp` / `jsonrpc` / `tools/call` / `sandbox` / `vm2` / `isolated-vm` 全量搜索**零实现**（仅命中 lucide 图标名 `Codesandbox`）
  - Skill 沙箱隔离执行机制不存在
  - 技术栈实际为 **Next.js 14.2.16 + Jest**，与约束要求的 **Vite + vitest** 根本性偏离
- **风险等级**：严重阻断
- **违反规范**：TS5 + React + Vite + shadcn/ui；@yyc3/core；MCP 协议；多 Agent 协作；Skill 沙箱隔离；@yyc3/store 三层适配器；vitest
- **修复建议**：先确认基座交付形态（私有 npm 包 / monorepo workspace / 本地相对路径），再补 `@yyc3/core`、`@yyc3/store` 依赖与适配器分层；MCP 与沙箱按插件化接口预留并实现最小可用版本。

### P0-5 类型体系双源冲突，类型安全失效
- **位置**：`app/types.ts` vs `app/data/integrations.ts:20-30`
- **证据**：两处各自定义 `Integration` 与分类类型，字段集合不一致；`app/types.ts` 的 `IntegrationCategory` 仅 **8 类**，而数据源 `categories`（`app/data/integrations.ts:114-145`）为 **29 大类**（+「全部分类」共 30 项）
- **风险等级**：严重阻断
- **违反规范**：单一数据源；TS 类型完整度
- **修复建议**：统一到唯一领域模型文件，`IntegrationCategory` 由 `categories` 数组派生：`type IntegrationCategory = (typeof categories)[number]`。

### P0-6 ESLint 完全失效
- **位置**：`eslint.config.js` + `package.json`（`eslint` v9 flat config）与 `eslint-config-next@14.2.16`
- **证据**：`npx eslint .` 抛出 `TypeError: context.getAncestors is not a function`，规则集无法加载；`next.config.mjs` 显式声明 `eslint.ignoreDuringBuilds: false` 却未见构建期 lint 生效
- **风险等级**：严重阻断（规范约束形同虚设，`no-explicit-any` 等规则全部未生效）
- **修复建议**：降级 ESLint 至 8.x 配合 `eslint-config-next@14`，或升级 `eslint-config-next` 至兼容 flat config 的版本（15+），并接入 CI 校验。

## 3. 一般优化点（P2）

1. **`any` 滥用 148 处 / 32 个文件**，热点：`app/services/ai/services/enhanced-recommendation.ts`(23)、`app/services/ai/core/prediction-engine.ts`(17)、`app/services/ai/services/user-behavior-analyzer.ts`(16)、`app/services/ai/core/ensemble-engine.ts`(14)、`app/services/database.ts`(12)。`eslint` 崩溃导致 `no-explicit-any` 规则完全未生效。
2. **JSDoc 覆盖严重不足**：导出声明 228 个，`@param`/`@returns` 仅 37 个（覆盖率 ≈16%）；「公共 API 必须单元测试」亦未达标。
3. **测试覆盖不达标**：真实执行 6 个 suite / 63 个用例，`jest.config.ts:34` 声明 50% 阈值，但 `collectCoverageFrom:25` 指向不存在的 `services/**`（实际为 `app/services/**`），覆盖率口径错误。
4. **分页能力不完整**：仅 `app/integrations/page.tsx`、`app/marketplace/search/page.tsx`、`app/marketplace/category/[category]/client-page.tsx` 具备真实分页；`app/marketplace/page.tsx:24-39,171` 使用 `.slice(0, 8)` 伪分页，未满足「应用市场分页列表」完整要求。
5. **`useSearchParams()` 缺 `<Suspense>` 边界**：`app/marketplace/search/page.tsx:4,17`，静态导出下为脆弱实现。
6. **类型断言掩盖缺陷**：`integration-card.tsx:86` 使用 `integration.id as string`，与 P0-5 的类型双源问题同源。
7. **Jest 配置与 Next 解耦不清**：`jest.config.ts:51` 使用 `createJestConfig`，但项目并非 Next 官方 jest 预设依赖链，配置语义易漂移。
